ADR-0007 · Needs block is absolute in the day-level dedicated-worker fail-safe

accepted subsystem N/A updated 2026-09-29
accepted subsystem: N/A ADR-0007

Context

  • In WorkPriorityUpdater.AssignDedicatedWorkersForDay, after the pass that assigns from goodWorkers, a fail-safe builds availableWorkers from all _capablePawns that are not in goodWorkers. That includes pawns that fail IsAllowedWorker. The fail-safe tries to reach max(target, MinWorkerNumber) when EnsureWorkerAssigned is set.
  • The fail-safe runs when schedule-aware selection is off, or when no allowed worker has a Work hour. The rule there is the combined rule (_managedWorkTypeRules, built from CombinedRules).
  • User decision G-3 (a), 2026-09-29: exclude only need-blocked pawns, and keep the fail-safe's existing AllowedWorkers behaviour identical (AC-24, AC-26). Option (b) is a follow-up.

Decision

Only the fail-safe's candidate loop changes: if (!goodWorkers.Contains(pc) && !rule.IsNeedBlocked(pc.Pawn)) availableWorkers.Add(pc);

  • IsNeedBlocked(Pawn) is the ADR-0006 instance method on the combined rule. It is not memoised, because the fail-safe runs rarely.
  • A code comment states that the fail-safe excludes need-blocked pawns only and deliberately does not apply AllowedWorkers (follow-up G-3 (b)).
  • No other path changes. Every other pass already goes through PawnCache.IsAllowedWorker, which now includes the needs check (AC-22, AC-25). When every eligible pawn is need-blocked, fewer workers are assigned, possibly none (AC-25).
  • Compatibility shims (WorkTab, PriorityMaster, MoreThanCapable): no new priority-write path. Priority 0 goes through the existing WorkTypePriorityHelper.SetPriority, so the shims are not affected.

Consequences

Positive

  • The absolute block holds on every assignment path, with a one-condition change.
  • With the filter Off or empty, IsNeedBlocked returns false before it touches the pawn. The candidate set and the resulting priorities are identical to the previous version (AC-26).

Negative

  • The fail-safe still bypasses AllowedWorkers and Pawn.WorkTypeIsDisabled. This pre-existing latent issue is knowingly left in place, so the two filters behave differently in this branch.
  • EnsureWorkerAssigned can now leave a work type with no workers. This is intended; the tooltips are reworded in ADR-0008.
  • AC-24 is verified by review and a manual in-game check, not a unit test. The candidate selection needs map and pawn state.

Alternatives considered

  • G-3 (b): restrict the fail-safe to allowedWorkers, rejected for this sprint by user decision because it changes existing behaviour (AC-26).
  • Memoise the need-blocked verdict on PawnCache, rejected because it adds state for a rarely run path (Simplicity Default).
  • Extract the candidate selection into a static helper for unit tests, rejected because it adds a new seam in a map-coupled method for a single condition.

Related ADRs

  • ADR-0006: defines IsNeedBlocked(Pawn).
  • ADR-0008: EnsureWorkerAssigned / MinWorkerNumber tooltip rewording.

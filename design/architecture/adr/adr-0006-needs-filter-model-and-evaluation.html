ADR-0006 · WorkManager-local needs filter on WorkTypeAssignmentRule

accepted subsystem N/A updated 2026-10-01
accepted subsystem: N/A ADR-0006

Context

  • Amended 2026-10-01: threshold → two-sided range at user request. The single lower threshold became an inclusive range [min, max] (FloatRange Limit, default 50%–100%, equivalent to the old 50% threshold), so the player can block a pawn whose need is too low or too high. The model, evaluation, validation and legacy migration below describe the amended behavior; the earlier "strictly below a threshold" wording is superseded.
  • Scope decisions (decisions-log 2026-09-29): a per-work-type needs filter that is WorkManager-local, because LordKuper.Common is an upstream contract and cannot be edited from this repo. It blocks a need level outside a per-need range, supports any need, ships no defaults, and the block is absolute. There is no hysteresis: the check is stateless and runs on every update.
  • The existing rule model is WorkTypeAssignmentRule : DefCache<WorkTypeDef>, IExposable. Nullable fields mean "undefined, inherit from the default rule". Combine(main, fallback) takes the value from main when it has one. Validate() runs only when saving. Settings load in the WorkManagerMod constructor, before defs are loaded.
  • Common precedent: PawnCapacityLimit : DefCache<PawnCapacityDef>, IExposable together with PawnFilter.FilterPawnCapacities (bool?) and PawnCapacityLimits (list). CombinePawnCapacities takes the source whose flag has a value and makes a shallow copy of its list. SatisfiesFilter skips entries whose def is unresolved and keeps no state.
  • DefCache<T> resolves lazily through DefProvider.Current.GetNamedSilentFail<T>. It latches on the first .Def / .Label read, so reading either before defs load caches null until restart.
  • Scribe_Collections.Look(..., LookMode.Deep) sets the list to null when the node is missing, which is the case for settings saved by older versions.
  • Convention conflict D-3: LordKuper.Common-1.6.md states "Pawn eligibility is expressed through PawnFilter … not ad-hoc predicates".
  • Evaluation choke point: PawnCache.IsAllowedWorker(WorkTypeDef) calls CombinedRulesDict[wt].IsAllowedWorker(pawn). The result is memoised per update and cleared on every refresh.
  • Tests target net472 with NUnit 4.6.1 and FluentAssertions 7.2.2. No existing test constructs a Pawn. Common exposes DefProvider.Current (a public, settable IDefProvider) as the def-lookup seam. Common's own tests construct defs with object initialisers.

Decision

Add a NeedLimit entry type and a tri-state needs filter to WorkTypeAssignmentRule, following the shape of Common's capacity limits. Evaluate it inside IsAllowedWorker through a pure static seam.

  1. Entry type. New internal sealed class NeedLimit : DefCache<NeedDef>, IExposable in Source/WorkManager/Settings/NeedLimit.cs.
    • Field: public FloatRange Limit = new(DefaultMin, DefaultMax); with internal const float DefaultMin = 0.5f and DefaultMax = 1f (AC-32). It is stored as fractions in [0, 1], the same scale as Need.CurLevelPercentage, and shown as 0–100%. The range is inclusive at both ends.
    • Constructors: NeedLimit() for Scribe, NeedLimit(string defName) and NeedLimit(NeedDef def).
    • public new void ExposeData() calls base.ExposeData() and persists Limit with Scribe_Values.Look (NaN sentinel default). Legacy migration: settings saved by the earlier build have a Threshold float and no Limit node; when loading reads no Limit but a Threshold, Limit becomes [threshold, 1], which preserves the old behavior. The load path touches only values, never .Def. Only the defName and range are persisted, never Scribe_Defs / LookMode.Def (AC-11). Unresolved defNames survive load and save (AC-12).
  2. Rule fields (after AllowedWorkers): public bool? FilterNeeds; (null = Inherit, false = Off, true = On) and public List<NeedLimit>? NeedLimits = [];. The list is nullable because Scribe can set it to null on load (AC-1).
  3. Persistence. ExposeData adds Scribe_Values.Look(ref FilterNeeds, …) and Scribe_Collections.Look(ref NeedLimits, …, LookMode.Deep), followed by if (Scribe.mode == LoadSaveMode.LoadingVars) ValidateNeedsFilter();. ValidateNeedsFilter reads only DefName and Limit (and, before the range exists, the legacy Threshold), so it is safe before defs load (AC-10, AC-11). Settings_Version is not bumped: the nodes are additive and optional.
  4. internal void ValidateNeedsFilter(), also called from Validate() on every save:
    • Sets NeedLimits ??= [] and drops null entries and entries with an empty DefName.
    • Removes duplicate DefNames (OrdinalIgnoreCase) and keeps the first (AC-3).
    • Resets a NaN min or max to NeedLimit.DefaultMin (0.5) or DefaultMax (1), clamps both with Mathf.Clamp01, and swaps them when min > max (AC-2).
    • On the default rule (DefName == null), sets FilterNeeds ??= false (AC-4).
    The method is internal because Validate() reads WorkManagerMod.Settings, which is not available in unit tests.
  5. Construction. CreateRule(defName) sets FilterNeeds = defName == null ? false : null and NeedLimits = [] (AC-4, AC-5). In DefaultRules, the default rule sets FilterNeeds = false explicitly. No shipped rule has entries or FilterNeeds == true (AC-6).
  6. Combine. var source = main.FilterNeeds.HasValue ? main : fallback; then FilterNeeds = source.FilterNeeds; NeedLimits = [.. source.NeedLimits ?? []];. This is a shallow copy, the same as PawnFilter.CombinePawnCapacities (AC-7, AC-8).
  7. Evaluation.
    • IsAllowedWorker(pawn) becomes AllowedWorkers!.SatisfiesFilter(pawn, Def) && !IsNeedBlocked(pawn) (AC-20).
    • internal bool IsNeedBlocked(Pawn pawn) => IsNeedBlocked(FilterNeeds, NeedLimits, def => pawn.needs?.TryGetNeed(def)?.CurLevelPercentage); is a one-line call into the static seam, which is the only place that checks the state.
    • Pure test seam: internal static bool IsNeedBlocked(bool? filterNeeds, IReadOnlyList<NeedLimit>? limits, Func<NeedDef, float?> getLevelPercentage).
      • Returns false when the state is not On or the list is empty (AC-19).
      • Skips entries whose Def == null (AC-18).
      • Skips a null level: the pawn lacks the need (AC-16) or pawn.needs == null (AC-17).
      • Blocks when level < Limit.min || level > Limit.max for any entry. The range is inclusive: a level equal to either bound passes (AC-14), and a [0%, 100%] range never blocks (AC-15, AC-13).
      • Keeps no state between updates (AC-21).
    • CurLevelPercentage is used rather than CurLevel because Food and MechEnergy have MaxLevel != 1 (audit R-1).
    • PawnCache is unchanged. It memoises the verdict per update and recomputes it on every update (AC-22, AC-23). Priority 0 is already the default outcome of UpdateCache, so no new write path is needed.
  8. Scoped exception to the eligibility convention (D-3). Pawn eligibility stays expressed through PawnFilter, except for this per-work-type needs filter on WorkTypeAssignmentRule. At design-promote, the convention line in LordKuper.Common-1.6.md is amended to cite ADR-0006. If Common later adds a needs dimension to PawnFilter, a new ADR supersedes this one and migrates the settings.
  9. Test approach (net472, no Pawn construction).
    • A new test-only FakeDefProvider : IDefProvider in WorkManager.Tests (dictionary-backed). It is installed into DefProvider.Current in SetUp and restored in TearDown. Fixtures that touch default-rule caches derive from StateIsolationTestBase. Because its generic constraints name Verse.Def, the type must load at NUnit discovery; how the test build makes Assembly-CSharp available for that is recorded in the ADR-0002 amendment (2026-09-29).
    • NeedDefs are built with new NeedDef { defName = …, label = …, listPriority = … }. If that needs the game runtime, the fallback is FormatterServices.GetUninitializedObject plus field assignment (the IsInitializedTests precedent).
    • The need-level check is tested through the static IsNeedBlocked with a dictionary-backed getLevelPercentage. A missing key means the pawn lacks the need; all-null values mean pawn.needs == null. This covers AC-13…AC-19.
    • ValidateNeedsFilter tests cover AC-2, AC-3, AC-4 and AC-10 (older settings simulated by setting the fields to null). DefaultRules tests cover AC-6, and Combine tests cover AC-7 and AC-8.
    • The real Scribe round trip (AC-9, AC-11, AC-12) and the one-line pawn.needs? adapter (AC-17) are manual in-game checks, following the sprint 001 MS precedent.

Consequences

Positive

  • Same shape as the existing tri-state rule fields and Common's capacity limits, so the code is familiar to reviewers.
  • Safe with older settings (the list is null-coalesced on load) and with removed DLCs or mods (entries are kept and skipped).
  • One evaluation point covers every gated assignment pass. The result is memoised per update, and the cost is negligible: a few linear TryGetNeed scans, made only while the state is On. The level-lookup delegate is allocated on every call (memoised per update), which is negligible.
  • The pure static seam makes AC-13…AC-19 unit-testable without building Pawn object graphs.

Negative

  • There are now two eligibility mechanisms, which is a documented exception to a project convention. DedicatedWorkerMode.PawnCount target counting does not see the needs filter. (The "Available pawns" preview does since 2026-09-30; see ADR-0008.)
  • Combined rules share NeedLimit instances with the source rule (shallow copy, as in Common). Edits in the settings window reach the combined rule before WriteSettings rebuilds it.
  • Unresolved entries are silently inert during evaluation. The only signal is the marker in the UI (ADR-0008).
  • The pawn.needs?.TryGetNeed adapter line and the Scribe round trip are not unit-tested; they are covered by manual checks.
  • Fast-changing needs (Beauty, Comfort, Food, Rest, Mood) can switch a work type on and off between updates. This is accepted by user decision (no hysteresis); the tooltip gives guidance.
  • Any future code that reads .Def / .Label of a NeedLimit on the load path would silently break def resolution until restart.

Alternatives considered

  • Persisted NeedDef → float dictionary, rejected because it needs LookMode.Def or manual key lists, breaks loading before defs, and diverges from Common's limit pattern.
  • FloatRange per need (like PawnCapacityLimit), rejected at the time because the scope was a lower threshold only. Adopted on 2026-10-01 at user request (see the amendment note above).
  • A separate NeedsFilter sub-object, rejected because it adds a layer for two fields when the rule already hosts sibling tri-state fields.
  • A needs dimension in Common's PawnFilter, rejected because Common is not editable from this repo (non-goal).
  • A per-entry predicate (float? level, FloatRange limit) as the only seam, rejected because it leaves the aggregation loop untested: the any-entry rule, the unresolved skip and the state gating.
  • Real Pawn / Pawn_NeedsTracker objects built through GetUninitializedObject and reflection, rejected as brittle against game internals (audit G-7).

Status: approved by the user on 2026-09-29 through AskUserQuestion ("Approve all (Recommended)"). No new package dependency, no new config flag and no change to Common. CA-4's GetAddableNeeds is consumed by ADR-0008.

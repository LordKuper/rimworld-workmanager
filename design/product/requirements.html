Work Manager — Product Requirements

5 goals 7 stories 45 AC 9 non-goals updated 2026-10-01

Problem

This document holds the persistent product requirements of Work Manager, grouped by feature set. Each feature set keeps the requirement IDs of the sprint PRD it was promoted from, prefixed with a feature code. Project vision and target users are in concept.html.

Feature set NF: Work-type needs filter

Promoted from sprint 002-work-type-needs-filters (PRD approved 2026-09-29). IDs NF-AC-n, NF-US-n and NF-Gn correspond to sprint 002 AC-n, US-n and Gn.

Work Manager assigns work types by skill, passion, schedule and allowed-worker filters, but without the needs filter it ignores pawn needs. A pawn can stay on Mining under an overhead-mountain roof until its Outdoors need falls to "cabin fever" or "trapped / entombed underground", and until rough rock and rubble push its Beauty need down to "unsightly" / "ugly". Without this feature the player has no way to say "do not assign this work type to a pawn while need X is outside the range Y%". Setting priorities by hand does not help, because Work Manager overwrites them on its next update.

Goals

NF: Work-type needs filter

  1. NF-G1

    Let the player block a work type for a pawn while any chosen need is outside a per-need range (0–100%, both bounds adjustable; amended 2026-10-01: threshold → two-sided range at user request). This works for any need and any work type. (from sprint 002 G1)

  2. NF-G2

    Make the needs block absolute. No assignment path assigns a need-blocked pawn, including EnsureWorkerAssigned / MinWorkerNumber and the dedicated-worker fail-safe. (from sprint 002 G2)

  3. NF-G3

    Fit the needs filter into the existing rule model. It inherits from the default rule, is saved and loaded with the other rule settings, is edited in the work-type rules UI and is shown in the rule summary. (from sprint 002 G3)

  4. NF-G4

    Change nothing for players who do not configure the filter. No needs rules ship by default, older settings load unchanged, and assignments are identical while the filter is off. (from sprint 002 G4)

  5. NF-G5

    Keep the feature robust for every player. Absent needs and needs from removed DLCs or mods never break evaluation, and all needs-filter UI text is localized in the three 1.6 locales. (from sprint 002 G5, product part; the sprint-scoped test and research-documentation parts are not carried over)

User stories

NF: Work-type needs filter

Mod player (colony manager) 7
  • as a mod player, I want to add any need, each with its own range, to a work type's rule, so that pawns whose need is outside that range are not assigned that work type (e.g. Mining with Outdoors and Beauty). (NF-G1; NF-AC-1, NF-AC-13…NF-AC-20, NF-AC-22, NF-AC-27, NF-AC-30…NF-AC-36)
  • as a mod player, I want to set needs limits once on the default rule and have work-type rules inherit or override them, so that I configure colony-wide limits in one place. (NF-G3; NF-AC-1, NF-AC-4, NF-AC-5, NF-AC-7, NF-AC-8, NF-AC-28, NF-AC-29)
  • as a mod player, I want the needs block to take precedence over "ensure worker assigned" and "minimum workers", so that a need-blocked pawn is never forced onto the work type. (NF-G2; NF-AC-24…NF-AC-26, NF-AC-41)
  • as a mod player, I want assignments to follow my pawns' current need levels automatically, so that a pawn goes back to the work type once its need recovers, without my intervention. (NF-G1; NF-AC-21…NF-AC-23, NF-AC-38)
  • as a mod player, I want the rule summary and tooltips to describe the needs filter accurately, so that I understand why a pawn is or is not assigned. (NF-G3; NF-AC-37, NF-AC-39…NF-AC-41)
  • as a mod player with existing settings or a changing mod list, I want my settings to keep working when I update Work Manager or remove a DLC or mod that added a need, so that I get no errors and lose no configuration. (NF-G4, NF-G5; NF-AC-2, NF-AC-3, NF-AC-6, NF-AC-9…NF-AC-12, NF-AC-18, NF-AC-35)
  • as a Russian- or Chinese-speaking player, I want the needs filter UI in my language, never as raw keys, so that I can use it. (NF-G5; NF-AC-42…NF-AC-44, NF-AC-49)

Sprint 002 US-8 (maintainer: unit tests, warning-free build, documented needs research) is sprint-scoped and not carried over. Its outcomes live in the test suite and in RimWorld-1.6.md.

Acceptance criteria

NF: Work-type needs filter

Terms used below. Needs state: the tri-state of a rule's needs filter. Inherit uses the default rule's needs filter, Off means no needs filtering, and On filters by this rule's entries. Entry: one NeedDef plus an inclusive level range. Need-blocked: blocked by the needs filter as defined in NF-AC-13.

Each NF-AC-n is sprint 002 AC-n. Sprint 002 AC-45 (needs research documentation), AC-46 (warning-free Release build), AC-47 (full test suite passes) and AC-48 (unit-test coverage list) are sprint-scoped process criteria and are not carried over, so NF-AC-45…NF-AC-48 are intentionally unused.

Related decisions

NF: Work-type needs filter

The design decisions behind these requirements are recorded in the ADRs below; this document does not restate them.

  • ADR-0006: Work Manager-local needs filter on WorkTypeAssignmentRule (model, inheritance, evaluation, persistence).
  • ADR-0007: the needs block is absolute in the day-level dedicated-worker fail-safe.
  • ADR-0008: needs UI, rule summary and localized strings.

RimWorld needs mechanics (Need / NeedDef API, level semantics, Outdoors and Beauty thought stages) are background in RimWorld-1.6.md.

Non-goals

NF: Work-type needs filter

  • Changing LordKuper.Common, including adding a needs dimension to PawnFilter.
  • Shipping needs rules for Mining or any other work type.
  • Lowering priority, instead of disabling the work type, for need-blocked pawns.
  • Hysteresis or latching (enter-low / exit-high) of the needs block.
  • Actively restoring needs (sending pawns outside, scheduling recreation). The filter only withholds work.
  • Per-need threshold hints or thought-stage markers on the slider.
  • Restricting the dedicated-worker fail-safe to allowed workers, and correcting the existing EnsureWorkerAssigned tooltip inaccuracy about the allowed-workers filter. Both are open follow-ups.
  • Legacy 1.1–1.5 builds and locales.
  • Per-pawn exemption from the needs filter.
